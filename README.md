# CyberSpace

Вебпроєкт CyberSpace із розділеною структурою frontend і backend.

## 📌 Про проєкт

CyberSpace — вебзастосунок, у якому клієнтська частина відповідає за інтерфейс користувача, а серверна частина забезпечує роботу CMS та API для керування вмістом сайту.

## 🛠️ Технології

- **Frontend:** Next.js, TypeScript
- **Backend:** Next.js, Payload CMS, TypeScript
- **API:** Payload REST API
- **Пакетний менеджер:** npm

## 📁 Структура проєкту

```text
CyberSpace/
├── frontend/   # Клієнтська частина сайту
└── backend/    # Серверна частина та Payload CMS
```

### Frontend

Містить клієнтський інтерфейс і компоненти, що відповідають за відображення сторінок та взаємодію з користувачем.

### Backend

Містить конфігурацію Payload CMS, API, колекції даних і глобальні налаштування вмісту.

Основні елементи:
- `src/collections/` — колекції даних CMS;
- `src/globals/` — глобальні налаштування, зокрема Header і Footer;
- `src/app/` — маршрути застосунку та API;
- `src/payload.config.ts` — конфігурація Payload CMS.

## ⚙️ Вимоги

Перед запуском установіть:

- [Next.js](https://nextjs.org/) — версію, сумісну з залежностями проєкту;
- npm, який постачається разом із Node.js.

## 🚀 Встановлення та запуск

### 1. Клонування репозиторію

```bash
git clone <URL-репозиторію>
cd CyberSpace
```

### 2. Запуск frontend

```bash
cd frontend
npm install
npm run dev
```

### 3. Налаштування та запуск backend

У новому терміналі:

```bash
cd backend
npm install
```

Створіть файл `.env` у папці `backend` і заповніть необхідні змінні середовища відповідно до конфігурації проєкту. Не публікуйте секретні ключі, паролі або значення змінних середовища у відкритому репозиторії.

Після налаштування запустіть backend:

```bash
npm run dev
```

> Якщо frontend і backend використовують однаковий порт за замовчуванням, задайте для одного з них інший порт відповідно до конфігурації. Точні команди запуску та змінні середовища перевіряйте у `package.json` і конфігураційних файлах відповідної частини проєкту.

## 🔐 Змінні середовища

Налаштування зберігаються у файлі `.env` серверної частини. Перелік обов'язкових змінних потрібно звірити з конфігурацією проєкту.

Не додавайте `.env` із секретами до Git. За потреби створіть `.env.example` із назвами змінних і порожніми або демонстраційними значеннями.

## 🧑‍💻 Розробка

Frontend і backend запускаються окремо, тому для локальної розробки зручно використовувати два термінали.

Перед внесенням змін перевіряйте доступні команди у `frontend/package.json` та `backend/package.json`.
